## Why 0.52–0.55 cannot create the database

This driver resolves the Metabase secret-value function at runtime: it prefers
`metabase.driver-api.core/secret-value-as-string`, which only exists from 0.56
on, and otherwise falls back to a candidate list of
`metabase.models.secret/get-secret-string` and
`metabase.secrets.models.secret/get-secret-string`, called with two arguments.
Upstream renamed that function to `value-as-string` in 0.52 — with the driver
argument added first — and moved the namespace to
`metabase.secrets.models.secret` in 0.55, so no candidate resolves on
0.52–0.55 and database creation fails before any query runs. Checked by
listing the class files and method arities inside each official fat JAR and
comparing them with the matching upstream source tag.

Covering 0.52–0.55 would need both the extra candidates and arity dispatch, and
covering 0.51.x `ARRAY` rendering additionally needs the driver to serialize
`java.sql.Array` itself, because those hosts do not. Per the supported-window
policy these are documented rather than backported: the fix for a user on
0.51.x–0.55.x is to move Metabase to the current stable minor.

## What still works everywhere

`select id, to_json(tags) …` returns the JSON string on every version tested
(0.51.14, 0.56.25.1, 0.60.15, 0.63.18). The 0.1.1 change makes the unwrapped
`ARRAY` read work inside the supported window; it does not remove the older
workaround.

## Not covered by this evidence

- **Full schema sync against a large project.** Metadata sync cost scales with
  the number of tables (mean ≈334 ms per table describe in the shared test
  project, which holds tens of thousands of tables), and the sync windows used
  for this artifact did not complete there. Recorded as not verified, not as a
  pass. The 0.1.0 artifact passed a full-sync E2E on Metabase v0.63.1.12; see
  `v0.1.0-metabase-v0.63.1.12.md`.
- Any Metabase release newer than `0.64.0`. Untested means untested.
- Metabase Cloud: this driver is not supported there.

## How to reproduce a cell

Verify the JAR against `SHA256SUMS`, put it alone in `plugins/`, start a clean
instance of the Metabase version, create the MaxCompute database, and run
`select id, <array_col>, <nullable_array_col> from <table>` as a native query,
comparing against the `to_json(...)` control. For a project without a
three-tier namespace, set `namespace-schema` to `false` in the connection
options; leaving it `true` aborts sync on such projects, which is a harness
pitfall rather than a driver defect.
